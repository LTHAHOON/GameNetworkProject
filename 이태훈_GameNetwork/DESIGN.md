# 설계 설명

## 게임 요구사항과 Host·Client가 맡는 역할
### 게임 요구사항
* Client보다 Host가 먼저 접속해 있어야합니다.
* Host 또는 Client가 접속되면 Online 텍스트가 표시되고 SpawnDelay만큼 기다린 후 플레이어 스폰이 되어야 합니다.
* 플레이어 스폰이 완료되면 WASD 이동이 가능해야합니다.
* 플레이어가 코인을 먹으면 해당 플레이어의 Score가 서버에 의해 1씩 증가해야합니다.
* 디스폰된 코인은 SpawnDelay만큼 기다리다가 재스폰이 되어야합니다.
* 영역을 넘을 정도로 많지 않는 이상 스폰될 때 코인끼리도 겹치면 안되고 플레이어끼리도 겹치면 됩니다.

### Host·Client가 맡은 역할
* Host가 맡은 역할은 서버 관리와 스폰, 코인 획득, 스코어 증가입니다.
* Client가 맡은 역할은 플레이어 이동입니다.

## 코인 게임 구성도와 요청·판정 결과가 이동하는 데이터 흐름
1.  코인은 비동기로 Trigger 반응을 기다리게 됩니다.
2. 플레이어가 코인을 Trigger시키면 RPC 호출를 통해 서버        공간에서 Score를 해당 플레이이의 스코어를 증가 시키고 해당 코인은 Despawn과 Destroy가 됩니다.
3. 그 순간 코인 Spawner에서 기록했던 Token을 통해 비동기적으로 진위(Cancel)여부를 판단하여 재스폰 과정을 거치게 됩니다.

## 사용한 자료의 출처와 주요 기술·통신 방식의 선택 이유

### 사용한 자료의 출처
* 다이어그램은 GitDiagram이라는 사이트를 활용하여 생성하였고 나머지 자료는 캡처입니다.

### 주요 기술·통신 방식의 선택 이유
* Unity 환경에서 안전하고 플레이어 제한없이 쉽게 만들기 위해 NGO 패키지를 선택하였습니다.
* 직접 빌드할 필요없이 빠른 테스트를 위해 Multiplayer Play Mode 패키지를 선택하였습니다.
* 빠른 입력 반응속도를 위해 플레이어의 Owner권한으로 움직이도록 하였습니다.

## 점수·코인 상태의 구조와 서버가 검사하는 규칙

### 점수·코인 상태의 구조
* 점수는 PlayerManager에서 기록되고 플레이어가 이를 불러오는 구조입니다.
* 코인같은 경우 풀링으로 동작하지 않고 토큰으로 생명주기를 확인하여 완전히 재생성을 하는 구조입니다. (아직은 필요없다고 판단하였습니다.)

### 서버가 검사하는 규칙
* 코인이 플레이어에 의해 트리거가 되었는가?
* 클라이언트 연결을 시도한 id가 유효하는가?
* 점수 증가량이 유효한가?

## UDP 위치 메시지의 네 필드·형식, 피어 식별 방식, 순서 번호와 최신 위치 관리 규칙

* 필드는 구조체 PeerMessageData 안에 프로퍼티(PeerID, PeerMessageNumber, PeerPos)를 선언하여 자동 필드로 구현되도록 하였습니다.
* 피어 식별은 string형 이름(PeerID)를 통해 육안으로 식별이 되게 하였습니다.
* 순서 번호는 PeerMessageNumber를 프로퍼티에 넣어서 메시지를 보낼 때 총 몇 번 보냈는지 확인하는 용도로 사용하였습니다.
* 최신 위치 관리 규칙은 현재 자신 PeerMessageData와 현재 상대 PeerMessageData를 멤버 변수로 선언하여 주고 받을 때마다 수정되도록 만들었습니다.

## 실시간 게임 상태와 오래 보관할 데이터의 구분
* PlayerAccount와 PlayerStatController를 명확히 구분하였고 PlayerAccount는 게임 플레이와 먼 현재 게임의 온라인 상태나 PlayerID를 가지고 있으며 PlayerStatController는 게임 플레이에 가까운 점수나 HP 등등(현재는 점수만)을 컨트롤하는 역할을 하게 됩니다.
* 프로토타입인 만큼 오래 보관한 점수 같은 데이터는 NetworkPlayerManager가 간단하게 관리하도록 하였습니다.

## 접속·종료·오류 등 운영 상태를 기록할 항목
* 접속 또는 종료는 텍스트를 통해 확인할 수 있으며 오류같은 경우 콘솔로 확인합니다.

## 참고한 코드와 직접 추가·수정한 부분
* 코인이 스폰이 될때 위치가 겹치는 문제를 해결하고 싶었는데 AI 피드백을 받아 응용하여 비동기 로직으로 동작할 수 있도록 만들었습니다.
* 그와 동시에 스폰하고 디스폰(Destory)될때 재스폰이 되도록 만들었습니다.
* 추가로 코인에 써먹은 Spawner 스크립트를 재활용하여 Player도 위치가 겹치지않게 만들었습니다. (NetworkConnector가 Player에 사용할 Spawner를 참조하여 기존 NetworkManager의 defaultPlayerPrefab 생성을 대신해줍니다. )
* 플레이어 ID를 데이터 베이스로 사용하지않고 간단하게 Guid로 사용하여 유니티상에서 서버가 작동중일 경우에만 데이터가 유지되도록 만들었습니다.
