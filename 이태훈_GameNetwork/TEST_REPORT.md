| NGO | (다른 게임 창)Host Connect Button 클릭 후 다른 버튼도 클릭, 작동안되는지 확인 -> Client Connect Button 클릭 후 Host Connect Button 클릭, 작동안되는지 확인 -> 플레이어 WASD 이동(서버랑 붙어있기) -> 씬창에서 코인 Transform Pos를 두 플레이어 근처로 강제로 먹이게 하기(한쪽만 스코어 증가되는지 체크) -> Disconnect Client Button와 Connect Client Button 클릭 빠르게 반복 -> Connect Client Button 누른 타이밍에 Online Status 체크 -> Score 유지 체크 -> 플레이어 중복 생성되는지 체크 | 양호 | 접속 후 Online Status: Online으로 표시되며 Score도 양호하며 플레이어 중복생성되지 않고 에러로그 없음 | 없음(버튼을 또 눌러도 문제없으며 콘솔에 기본 로그가 나오도록 하였음)  | 양호 |
| UDP | 두 커미널에 dotnet run <내 포트> <상대 포트> <이름> 입력(한쪽은 이름을 전송량 제한값보다 클 정도로 입력) -> 전송량 조건 비교가 에러없이 잘 되는지 확인 -> 이름 다시 입력(정상적으로) -> 0(전송모드) 선택 -> 변경할 위치 입력 및 전송 -> 상대 터미널에서 받았는지 확인 -> 상대 터미널도 이와 같은 방식으로 위치 전송 및 확인 -> 같은 위치 입력 -> 무시되었는지 로그 확인 ->  1(무시된 메시지 보기) 입력 -> 무시된 메시지인지 확인 -> 0(뒤로가기) 입력 -> 0(전송모드) 입력 -> 숫자아닌 문자나 기호 입력해서 다시시도되는지 확인-> 3(나가기) 입력 -> 에러없이 나가지는지 체크 | 문제 1(전송량 조건 비교를 넣지 않으면 이름 비정상적으로 길게 지을 때 에러가 발생하거나 데이터가 잘려나가는 문제가 생긴다는 것을 알았음) | 위치 송수신 성공적으로 잘되며 같은 위치를 입력하였을 때 수신되지 않고 무시된 메시지로 기록되는 걸 확인하였음. | 이름같은 경우 string 가변 데이터이기 때문에 전송량 제한걸어서 안정적이게 송수신하도록 수정하였음 (위치 데이터나 순서번호는 int 4바이트 고정이기 때문에 제한에 굳이 포함하지않았고 이름을 만들고 시작하기 때문에 처음부터 조건을 걸었음) | 양호
